### 2.3 权限审计说明

执行:

```bash
PYTHONPATH=backend .venv/bin/python scripts/audit_vkpi_scope_permissions.py --json
```

结果显示 `status=fail`, `endpoint_count=749`, `unguarded_endpoint_count=5`。但逐项复核后,至少 4 个属于审计脚本口径落后:

| 被标端点 | 真实情况 | 处理 |
|---|---|---|
| `GET /budgets` | 代码用 `Depends(require_manager_tab("vkpi","read"))` | 审计脚本 `GUARD_TOKENS` 未包含 `require_manager_tab` |
| `GET /budgets/usage-by-provider` | 同上 | 同上 |
| `GET /budgets/usage-by-cron` | 同上 | 同上 |
| `POST /gtm/verdicts/{id}/decide` | 代码用 `Depends(require_manager_tab("vkpi","write"))` | 同上 |
| `GET /api/portal/kol/{token}` | 公开 token 隔离只读门户 | 应列入 token-public allowlist 或独立 token guard 检查 |

严苛结论:目前权限实现不一定有这 5 个洞,但审计脚本本身已经不可信。下一步应先修审计工具,让它识别 `require_manager_tab/require_manager_staff/token public`。否则安全报告会把真风险和误报混在一起。

## 8. 最终结论

如果只看“代码能不能构建、测试能不能跑”,当前本地前后端已经比较强:后端 1079 测试、前端 352 测试、tsc/build 都过,hardening error 也归零。

如果按“发布前最严苛生产标准”看,当前仍有两个硬门没过:

1. 本地 runtime 没有对齐当前 HEAD。
2. 业务结果闭环还没形成真实 outcome/eval。

所以当前阶段应定义为:

> 工程骨架已进入强 Beta,但还未进入生产闭环 Beta。

下一步最正确的动作不是继续大规模扩功能,而是先把 runtime 对齐、权限审计工具修准、一个 SKU 的 outcome/eval 跑通。做到这三件事,V-KPI 才能从“聪明的系统骨架”进入“可被事实校准的增长大脑”。
