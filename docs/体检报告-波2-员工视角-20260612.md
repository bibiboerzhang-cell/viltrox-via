## 红单(断点,按疼痛排序,2)

### R1 [中高 · 越权/隐私] 重型 `/task-queue` 端点完全不遮蔽,绕过 compact 的泳道隐私
- **断点**:泳道隐私遮蔽 `_apply_viewer_visibility` **仅**在 `get_task_queue_compact` 内调用(`queue_view.py:663,685`)。而重型兄弟端点 `GET /api/admin/vkpi/kol-pool/task-queue`(`vkpi_kol_pool.py:1203-1216`)路由体 **`del staff`**、调 `get_task_queue(...)` **不传 viewer**,对 vkpi-read 员工返回**未遮蔽**的他人任务 label + `search_session` 会话入口。
- **影响**:员工绕开前端、直接打 `/task-queue` 即可读到本应只对本人/管理员可见的他人任务内容与会话入口,「主管裁令」隐私硬化(只在 compact 落地)被同数据的另一路径架空。
- **实证**:`vkpi_kol_pool.py:1211` `del staff`;`grep _apply_viewer_visibility` 仅命中 `queue_view.py:663,685`(均属 compact)。实测两端点活动队列均空(active=0/recent=0,无法现场出帧),为代码级可证断点。
- **建议**:`get_task_queue` 路由同样接 viewer 并复用 `_apply_viewer_visibility`,或在领域层默认遮蔽、对 admin 豁免。

### R2 [低中 · 遮蔽不完整] 合同收款金额/付款节奏经 fee_amount 与 raw 摘要旁路可见
- **断点**:`_PAYMENT_KEY_RE`(`vkpi_projects.py:29`)只按**键名** `payment|account|iban|swift|bank|payee|beneficiary|routing` 遮值。合同 id 10 员工视角:`payment_terms` 已遮为 `***`,但同一收款信息经下列字段对非成员员工仍可见 —
  - `fee_amount = 12500`、`fee_currency = "USD"`(键名不含 fee,未遮)
  - `manual_overrides_json.fee_amount = 12500`(未遮)
  - `raw_extracted_json.summary` 自由文本:「总费用12,500美元,分两期支付(签约50%、完成50%)…」(付款节奏散文,键名 summary 不匹配,未遮)
- **定性**:`fee_amount` 经 detail 费用 tab(`cash_fee` 运营自录口径,见绿单7)本属**设计内**可见;真正的旁路缺口是 **raw/摘要类自由文本**会回声付款节奏/路由,key-regex 只盖结构化键、盖不住散文值。本样本摘要未含银行账号(真正敏感的 ACH/W-9 在 payment_terms 中已被遮),故疼痛偏低;但口径上「遮了 payment_terms 却留 fee_amount + 摘要」对用户呈现不一致。
- **实证**:`GET /projects/3998/contracts` 员工 vs admin diff(见绿单5)。
- **建议**:明确「收款遮蔽」边界——若 fee_amount 属可见则在 UI 标注口径一致;若需收口,对 `raw_extracted_json`/`manual_overrides_json` 的 summary/notes 自由文本做值级关键词遮蔽,而非仅键名。
