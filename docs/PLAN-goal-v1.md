# V-KPI 目标模式 · 总计划 v1

> Commit file: `docs/PLAN-goal-v1.md`
> Rule: after every new session or context compaction, read this file before touching code.
> Scope: this is the continuous execution target mode. It does not change permissions, gates, or V6 Fit safety boundaries.

## 1. 总目标

整体完善度从 35 提到 50。

上线条件是“上线门 v1.0 替换版”全绿，缺一不换。

角色不变:

- Codex: 执行。
- Jianbo: 判断 + 浏览器验证。
- Claude: 架构审查。

目标模式改的是连续执行，不是权限。四闸照停。

## 2. 铁律

每日自动对账。违反即全停。

1. `viltrox_fit_score` / `viltrox_fit_reason` 零写入，每日对账 SQL 结果存档。
2. 禁 `git add .` / `git add -A` / `push`；一原子改动一 commit。
3. 评分语义冻结：`rule_v0` / V6 公式 / rubric prompt 不动。
4. 生产 env 变更必须出现在当日报告。
5. 连续 2 次同类失败，停下报告等指令，禁自我变通绕过。

P4 维护窗定义 v1.2：冻结仅约束“存在 running 任务，或 60 秒内有任务可被 claim”的时段；全部 queued 均带未来 `next_retry_at` 属于合法维护窗，worker 侧改动可在人审后进窗。账本脚注随批：注明哪些任务跨了代码版本，例如 `308` 第 4 次起运行于 FIX-1 之后。

## 3. 四闸

到闸即停，人批后过。

| 闸 | 类型 | 触发条件 |
| --- | --- | --- |
| 闸A | 资金 | 单批预估超过 `$10` 的 LLM 调用，启动前报预算 |
| 闸B | 结构 | migration / 删除文件或页面 / 单文件改动超过 500 行 |
| 闸C | 语义 | 分数字段命名、展示语义、UI 文案层级变更 |
| 闸D | 上线 | 门卡逐项对表，Jianbo 终审 |
