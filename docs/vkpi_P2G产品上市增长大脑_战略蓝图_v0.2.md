# P2G 产品上市增长大脑 · 战略蓝图 v0.2(2026-07-07)

> 本文取代 docs/vkpi_新发展方案_P2G…(v0.1)与 docs/vkpi_市场增长大脑_定位升级…。v0.2 采纳三项裁决:①显示层宪法 ②平台数字降格为规则库 ③GTM-0 审计先行的新波次。**这是执行蓝图不是终版**——未验证的平台数字不写成系统宪法。

## 一、定位(一句话)

Product-to-GTM Brain 不是找 KOL 的工具,而是**新品上市后的增长决策系统**:把产品、市场、KOL、Dealer、官号、独立站、内容、预算和历史结果合成一份可执行 GTM Plan,并通过 Action Inbox 和 Learning Brain 持续变准。

## 二、决策链(替代五脑并列图)

```
产品输入 → 产品理解 → 市场选择 → 渠道组合 → GTM Plan
       → Action Inbox(人审)→ 执行结果 → 学习回流 → 下一次推荐更准
```

五脑是决策链的器官归属,不是并列模块:Product(理解)/Market(选择)/Channel(组合)/Action(执行)/Learning(回流)。

## 五、显示层宪法:聪明藏在系统里,结果露在路线图上

**核心原则:V-KPI 不展示"系统怎么聪明",只展示"该怎么赢"。** 所有复杂感知、评分、预测、竞品信号、KOL 风险和渠道推演沉在内部;界面只输出主判断、路线图、行动清单、触发条件、撤退条件和复盘学习。

**不展示**:评分公式与权重/内部推理过程/敏感竞品监控细节/KOL 失败黑名单(只显风险标签)/原始评论大段(只显归纳信号)/数据源明细(只显来源类型+样本量+新鲜度+置信度)。**预测永不说成绝对结果**——用情景+条件+撤退线表达。

**技术合约(信息分级)**:
```
{ public_plan:  { thesis, forecast, roadmap, channel_mix, next_actions,
                  risks, confidence, decision_basis_summary },
  private_evidence: { score_details, raw_sources, competitor_notes,
                      model_features, debug_trace } }
```
`private_evidence` 默认不返回前端,仅 admin/debug/离线审计;页面只吃 `public_plan`。

**条件化预判格式(强制模板)**:预判(机会陈述)→ 依据(信号归纳+置信度)→ 触发加码(量化条件)→ 撤退条件(量化条件+替代路线)。示例:「300W EVO 在美国摄影配件人群有 14 天内容放大机会;依据:同类内容完播与购买意向评论上升+相近 SKU 历史转化;加码:48h 内 3 条视频完播进账号 30 天前 25% 且短链点击成本低于阈值→进 Spark/联盟放大;撤退:10 个 KOL 样本有效回复低于目标或 Dealer 区域转化持续低于基线→转官号教育内容+独立站承接。」

## 六、增长打法规则库(Growth Playbook,非系统真理)

平台研究的全部数字(TT 完播 70% 病毒门槛/2s hook≥40%=A 档/Spark+43% 禁自产素材直投/美区 2/3 销量=达人短视频挂车/IG sends 非粉 3-5×/YT CTR≥4% AND 留存≥40%/佣金 10-15%+阶梯/每变体≥1000 曝光/情绪两轴+器材四情绪/伦理闸)**一律入规则库表,每条带 `basis / source / confidence / sample_size`,可被自有数据推翻更新**——不硬编码为真理。落点:GTM-2 编码进记分卡与内容处方时逐条登记;学习账本用自有数据持续校准(镜头类目公开基准缺失,自建基线)。

## 八、不做什么(边界)

不做通用 SaaS(多租户时间锁)/不做全自动执行(人审是特性不是缺陷)/不做黑帕特情绪操纵(伦理闸)/不把预测装准(条件化预判)/不在页面堆分析(显示层宪法)/不追 GNN 等重架构(数据规模不配)。

## 九、数据护城河(宪章不变)

产品级理解 × 视频内容深析 × 真实履约数据 × 销售渠道联动 × 长期记忆——通用 KOL SaaS 无法快速复制,因为它们没有我们的内部业务闭环。
