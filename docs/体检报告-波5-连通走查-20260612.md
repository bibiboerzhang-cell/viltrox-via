## 红单(断点,按疼痛排序,8 条)

### R1 · 收藏行「合作结果直连 assignments」彻底失效——projects_json 是字符串,前端按数组判空
- **环**:① Pool 收藏→MY KOL 显形(合作列+漏斗 stage 全错回退)。
- **实证**:后端 `pool_favorites.py:96-104` 用 `json_agg(...) AS projects_json`,HTTP 返回为 **JSON 字符串**(admin 实测 `"projects_json":"[{\"project_id\": 4044, ...}]"`,附录 A1);前端 `MyKolPage.tsx:493` `Array.isArray(fav.projects_json)` 恒为 false → rawAssignments=[] → synth=[] → 回退 platform:handle 匹配——而 `:491-492` 注释自述该匹配"对 769 收藏几乎全 miss"。2026-06-12 的「裁令重修」实际是死代码。
- **修法**:`MyKolPage.tsx:493` 改为 `typeof fav.projects_json === 'string' ? JSON.parse(fav.projects_json) : (Array.isArray(...) ? ... : [])`(或后端 list_favorites 落 items 前 `json.loads`)。

### R2 · 泳道账号分析→MY KOL 定位被选中重置竞态吃掉(首次切页必失效)
- **环**:④ 泳道→所属对象。
- **实证**:`MyKolPage.tsx:439` 挂载即消费 pending 设 `selectedKolId='pool:<id>'`;但 favorites 是异步加载(`:460-469`),首帧 `filteredItems` 只有 base 行,不含 `pool:<id>` → `:551-559` 的兜底 effect 立刻把 selectedKolId 重置为 preferred 行 → 收藏行加载完成后定位已丢。v615 切 nav 会卸载重挂 MyKolPage(`V615ReplicaApp.tsx:875-883` AnimatePresence 按 activeNav 渲染),所以"从泳道点开"恰好走的就是这条必败路径。
- **修法**:`:551-559` 重置前豁免"pool: 前缀且 poolFavorites 尚未加载完"的场景(如增加 `favLoaded` 状态,未 loaded 时不重置)。

### R3 · v615 项目详情点 KOL 是死点击——onOpenKolProfile 接了空函数
- **环**:③ 项目详情点 KOL→Drawer。
- **实证**:`V615ReplicaApp.tsx:917` `onOpenKolProfile: () => undefined` → `ProjectParticipationTab.tsx:156-164` KOL 名按钮 onClick 调用之,样式呈可点击但什么都不发生。KolProfileDrawer 链路只在旧 VkpiDashboard 壳(`VkpiDashboard.tsx:315-336,586-595`)接通,v615 复刻壳整环断开。
- **修法**:在 V615ReplicaApp 接最小 KolProfileDrawer(复用 handleOpenKolProfile 逻辑),或暂不传 handler 让 `is-clickable` 态消失(`ProjectTable.tsx:91` 已支持 undefined 降级,ParticipationTab 需同样判空)。

### R4 · C6 语义如实记:「从 MY KOL Pool 添加」实为全池候选,非 My KOL 限定
- **环**:② 项目选择器语义。
- **实证**:弹窗标题 `ProjectDetailModals.tsx:570` 写"从 MY KOL Pool 添加";后端 `workflow_projects.py:593-653` SELECT 全表 `vkpi_kol_pool`,仅排除已加入本项目者,无 favorites/staff 过滤。HTTP 实证:employee favorites 总数=1,而 available 候选返回 500 条(limit 截断,附录 A3)。另:MY KOL 行侧不存在"加入项目"入口(grep 全 myKol 目录无该动作),方向只有项目详情→选择器一条。

### R5 · 泳道 kind=合同提取 无所属对象路由(发票提取/合同润色同病)
- **环**:④ 泳道→所属对象。
- **实证**:`openTaskOrigin`(`TaskProgressBoard.tsx:120-128`)只识别 kol_profile 与 search_session 两类;`taskCanOpen`(`:130-132`)对其余返回 false → 条目禁用。DB 实证:`project_contract_extract` 任务 target_type='project_contract'(4 条,附录 B1),两分支都不命中;payload 里明明有 project_id(`contract_assist.py:296` 同族任务 target_type='project'/target_id=project_id)却无路可回项目归档 tab。

### R6 · KOL Drawer 合作历史「回项目」只对来源项目可点,其余历史项目无门
- **环**:③ Drawer 合作历史→回项目。
- **实证**:`KolProfileDrawer.tsx:126` `projectForOpen = fallbackProject && projectId === fallbackProject.id ? fallbackProject : undefined` → `:132` "打开项目详情"按钮仅来源项目渲染;profile.projects 里其它合作项目(admin 实测 kol 58 有项目 37)只能看不能跳。
- **修法**:onSelectProject 改收 projectId,上层用 `data.projects.find(p => p.id === projectId)` 或直接 `projectDetailDrawer.openProjectDetail({id})` 兜底,按钮对所有行渲染。

### R7 · 泳道「最近完成」给无 target 的账号分析标"可打开",点了无声无息
- **环**:④ 泳道→所属对象(次级)。
- **实证**:`TaskProgressBoard.tsx:296` 过滤条件 `taskCanOpen(task) || task?.kind === "账号分析"` 故意保底显示无 session 的账号分析;但 `:374-377` 最近完成按钮 onClick 无条件 `openTaskOrigin(task)`,且区块头 `:371` 统一标"可打开"——对无 target 的条目 openTaskOrigin 两分支都 no-op,点击零反馈。
- **修法**:按钮按 `taskCanOpen` 置 disabled 并去掉/条件化"可打开"标签。

### R8 · 环⑤如实记现状:Dashboard 无「收藏卡」;CommandCenter「KOL 合作漏斗」卡纯展示不可点
- **环**:⑤ Dashboard 卡片→对应页。
