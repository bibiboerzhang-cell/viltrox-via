6. **pgvector 未装**(pg_extension 仅 plpgsql)→ memory 层照设计落地需先装扩展 + embedding key。
7. 宣称口径偏高:api-spec 实数 ~51 端点(宣称 70+);"7 个 tab" 实为 5 实 + 2 占位(现场/复盘 = PlaceholderTab)。

## 5. 建议:**B(仅 mockup 连给团队预览)**

理由:
1. **B 的边际成本≈零**:修复与接线已经在仓内完成(EventsMockupPage 已挂、nav 已有、样式无缺口),不选 B 等于退掉已付清的货。
2. **A 当下不可开**:交付包表面"开箱即用",实测三道硬墙(events 表名撞 party layer、users.id 类型全套不符、后端 TS 全部要重写成 Python),真实成本 ~25 窗级,在 KOL Pool 波次收口前开第二战线必然双线失血。
3. **C 与 B 同价但负收益**:nav 入口已存在,C 不摘入口=团队照样点进无人认领的 mock;摘入口又违背本波零代码铁律。B 用同样的 0.5-1 窗换来真实反馈,反馈再决定 A 是否值 25 窗。
4. **若未来升 A,先做三件纸面前置**(已写入本单):全套表改名 `vkpi_events_*`;FK 改 bigint 对齐 users;integrations 按 Python 重估——届时以本单第 1-3 节为施工底稿,zip 仅作 schema 参考、不得再解压覆盖。
