# 07｜Epic 工作包、排期与 RACI

## 1. 估算口径

- `人周` 是一个有对应能力的人一周的有效交付量，包含实现、测试、遥测、审计、文档和修复。
- 估算基于 AI 辅助的 8–10 人成熟团队，误差建议按 ±30% 管理。
- 工作包总量约 246 人周；其余容量用于产品研究、跨团队沟通、缺陷、发布和风险缓冲。
- 迁移、安全、账单和恢复任务不能用生成代码速度简单压缩。
- 每个 Epic 要进入项目管理工具拆成 1–3 天可验收任务，并关联本文的退出条件。

## 3. 各 Epic 必拆的任务类型

每个 Epic 默认包含：

1. ADR/产品规则与非目标。
2. 数据模型与迁移、回填、验证、回滚。
3. 服务端权限、权益、Flag、配额和审计接线。
4. API 合同、幂等、并发、错误语义。
5. 页面及加载、空、错、降级、权限状态。
6. Metrics、Logs、Traces、告警和操作手册。
7. 单元、集成、跨租户、浏览器、容量与故障测试。
8. 发布/灰度/回滚、验收证据和用户文档。

若某项不适用，任务必须写明原因，不能默认为“以后补”。

## 5. RACI

角色：

- PO：产品负责人
- TL：技术负责人
- BE：后端/数据
- FE：前端
- SRE：平台/SRE
- QS：QA/安全
- PD：产品设计
- FO：财务/运营

R=负责执行，A=最终负责，C=参与评审，I=知会。

| 工作流 | PO | TL | BE | FE | SRE | QS | PD | FO |
|---|:---:|:---:|:---:|:---:|:---:|:---:|:---:|:---:|
| 内部 9.5 定义 | A | R | C | C | C | R | C | I |
| 租户上下文/隔离 | C | A | R | C | R | R | I | I |
| IAM/策略/紧急授权 | C | A | R | C | C | R | C | I |
| 套餐/权益 | A | C | R | R | I | C | R | R |
| 公司生命周期 | A | R | R | R | C | C | R | C |
| 区域/部署/发布 | I | A | C | C | R | R | I | I |
| 模型/供应商 | C | A | R | C | R | R | I | C |
| 配额/成本/账单 | C | C | R | C | C | C | C | A/R |
| 公司控制台 | A | C | R | R | I | C | R | C |
| 用户工作台 | A | C | R | R | I | C | R | I |
| 审计/隐私/合规 | C | C | R | C | R | A/R | C | I |
| GA 决策 | A | A | C | C | C | R | C | C |

任何 L4 操作的设计或上线不能由一个人同时承担 A、实现、审批和验收。

## 6. Definition of Ready

进入开发前必须具备：

- 明确目标用户、当前痛点、成功指标和非目标。
- 所属控制层和完整资源/动作/作用域。
- 数据所有者、组织/区域/等级/保留/删除规则。
- 权益、权限、Flag、配额和风险等级。
- API/事件草案和失败/并发语义。
- UI 关键状态和可访问性要求。
- 迁移、依赖、灰度、回滚和遥测计划。
- 可执行验收案例；外部依赖和负责人明确。

缺少租户边界、权限或数据归属的任务不能以“先做页面”进入开发。

## 7. Definition of Done

一个任务只有同时满足以下条件才 Done：

- 代码与迁移通过审查，无未说明的旧路径旁路。
- 单元/集成/浏览器/跨租户测试按风险通过。
- 关键并发、重试、幂等和故障行为验证。
- 权限、权益、Flag、配额、审计接线完成。
- Metrics/Logs/Traces 和告警可用，敏感字段检查通过。
- 页面包含加载、空、错、无权、未购买、配额和降级状态。
- 灰度和回滚在目标环境实际演练。
- 操作手册、用户说明和已知限制更新。
- 生成带 Git SHA、环境、数据时间的验收证据。

## 10. 变更管理

- Scope 变更由 PO + TL 评估对关键路径、迁移和验收的影响。
- 新增 GA 必须项时，等量移出可延后范围或调整日期/团队。
- 不因接近里程碑而把阻断项重标为普通已知问题。
- 任何跨租户、安全、计量和删除缺陷默认提升优先级并重新评估已发布范围。

## 11. 项目看板建议

列：`Discovery → Ready → In Development → In Review → Security/Data Review → QA → Release Candidate → Verified → Done`。

标签：阶段、控制层、模块、风险等级、租户迁移、数据等级、是否计费、是否需要审批/迁移/浏览器测试。

禁止只用“前端完成/后端完成”代表用户能力完成；一个用户旅程跨前后端、数据、权限、运行和审计共同验收。
