# 05｜运行、安全与成本治理

## 1. 运行治理目标

平台必须能在不读取租户业务正文的情况下回答：某家公司运行在哪、使用哪个版本和模型、还剩多少配额、成本是否异常、服务是否健康、一次变更影响谁、是否可以安全回滚。

## 2. 区域与部署

### 2.1 区域能力模型

每个 Region 声明：

- 司法辖区与数据驻留标签。
- PostgreSQL、Redis、队列、对象存储、搜索/向量设施。
- 可用模型供应商和网络出口。
- KMS/Secret 域、备份位置和日志/审计位置。
- 支持的模块和版本。
- 软/硬容量、暂停接收新租户阈值。
- 主备关系、RTO、RPO 和最近演练证据。

公司开通时绑定主区域。区域不是一项随意可改的普通设置；迁移需复制、验证、切流、观察和旧数据清理状态机。

### 2.2 部署模式

| 模式 | 用途 | 隔离 | 首发建议 |
|---|---|---|---|
| 共享 Cell | 中小客户 | 共享计算，数据库/RLS/存储/队列强租户隔离 | 默认 |
| 专属 Cell | 大客户/高负载 | 专属服务与队列，可共享区域基础设施 | P1 |
| 私有化 | 监管/内网客户 | 客户环境内完整部署 | 独立产品线，不阻塞 SaaS GA |

共享 Cell 应限制“爆炸半径”：单个 Cell 的租户数、并发、队列和数据库容量有硬上限，异常租户可隔离到专用队列或 Cell。

### 2.3 部署选择顺序

`organization → primary region → deployment/cell → environment → release channel → release version`。

任何环节未知时失败关闭。后台任务保存创建时的部署身份；Worker 处理前再次验证公司状态和部署归属。

## 3. 模型与供应商治理

### 3.1 供应商账户类型

- 平台托管共享 Key：适合标准套餐，平台负责轮换、成本和配额。
- 平台托管专属 Key：成本与限额独立，适合企业套餐。
- BYOK：客户密钥进入区域 KMS/Vault，平台仅保存引用和健康状态。

应用数据库不保存可直接解密所有客户密钥的平台主密钥。密钥访问由工作负载身份和精确用途授权；前端永不回显明文。

### 3.2 模型策略解析

优先级：

`平台安全禁用 > 区域/数据合规 > 公司策略 > 套餐模型权限 > 项目策略 > 用户偏好`。

每项任务绑定精确模型和 Fallback 链：

- Fallback 只能在同一合规/质量等级内。
- 禁止在失败时静默切到未批准供应商或更昂贵模型。
- 精确模型必须通过实时探测、生产就绪证据、预算预留和熔断检查。
- 模型切换先发布策略版本，再内部/公司灰度，支持一键回到旧版本。

### 3.3 每次 AI 调用记录

```text
organization / membership / project / module / feature
region / deployment / release
provider_account / exact_model / model_policy_version
input_tokens / output_tokens / cached_tokens
provider_request_id / request_id / trace_id
reservation_id / pricing_version / provider_cost / billable_units
data_classification / tool_calls / result_status
```

提示词正文不进入普通运行指标；调试采样需单独授权、脱敏、限期保留。

### 3.4 健康与熔断

- Provider 与精确模型分开探测。
- 状态为 `healthy/degraded/open/disabled/unknown`。
- 连续失败、延迟、429、内容安全错误和成本异常分别计数。
- 熔断打开后优先排队/降级/拒绝，不自动跨越合规边界。
- 恢复采用半开小流量验证。

## 4. 配额、预算和计费

### 4.1 统一指标

| 类型 | 指标示例 |
|---|---|
| 席位 | active members、管理员、服务账号 |
| 请求 | API、查询、报告、工作流、智能体运行 |
| AI | input/output/cached tokens、图片/视频秒数 |
| 数据采集 | 抓取对象、页面、评论、视频、Provider 单元 |
| 数据 | 存储 GB 月、向量数、导出行数、网络流量 |
| 计算 | 并发任务、Worker 秒、GPU 秒、长任务时长 |
| 商业 | 客户 Credits、供应商成本、超额计费、折扣 |

### 4.2 作用域

平台、区域、公司、套餐、部门、项目、用户、模块、功能、供应商和模型。下级分配之和不能超过上级硬额度，除非上级允许弹性共享。

### 4.3 执行流程

1. 请求估算最坏/合理用量。
2. 对公司、项目、用户、功能和 Provider 做原子预留。
3. 成功获得预留后才调用付费供应商。
4. 调用完成按实际使用结算，多余释放。
5. 超时/未知结果进入待对账，不立即重复调用。
6. 每日对供应商明细、内部成本事件、计量事件和客户账本。

所有付费调用必须走统一入口；旧网关的非原子模式进入阻断清单并逐步移除。

### 4.4 阈值行为

| 阈值 | 默认行为 |
|---:|---|
| 80% | 通知用户/管理员，显示预计耗尽时间 |
| 90% | 通知公司 Owner/财务，限制低优先级后台任务 |
| 100% | 按套餐硬停、降级或进入明确超额计费 |
| 异常增速 | 临时降低并发、要求确认、通知平台运营 |

不能在达到 100% 后既继续调用又不产生明确账单；也不能把预算阻断显示为模型故障。

### 4.5 成本与价格分离

- `provider_cost`：平台实际支出，按供应商价格版本计算并对账。
- `billable_usage`：客户套餐定义的计量单位。
- `invoice_amount`：用量、套餐、折扣、信用和税的商业结果。
- `internal_allocation`：公司内部部门/项目分摊，可与客户账单不同。

母控制台可看全部；公司财务默认看账单/公司分摊，不必看到平台底价；用户按公司政策看单位或金额。

## 5. Feature Flag、Entitlement 与 Kill Switch

| 控制 | 回答的问题 | 谁管理 | 失败行为 |
|---|---|---|---|
| Entitlement | 客户购买了什么 | 商业/平台运营 | 拒绝并提示升级 |
| Feature Flag | 新版本对谁生效 | 发布/产品 | 回到稳定变体 |
| Kill Switch | 风险能力是否立即停用 | 安全/运维 | 停止新执行并按语义处理运行中任务 |
| Permission | 这个人能否操作 | 平台/公司管理员 | 拒绝并可申请权限 |
| Quota/Budget | 现在还能用多少 | 平台/公司财务 | 硬停、降级或超额 |

每个业务入口、Worker、Scheduler 必须调用同一中央 Evaluator；业务模块不能用散落 `if flag` 自行解释。Flag 规则有 Owner、到期和清理任务，避免永久实验配置。

## 6. 发布与升级

### 6.1 发布制品

每个 Release Artifact 绑定：

- Git SHA、不可变镜像摘要、前端制品哈希。
- SBOM、依赖漏洞扫描、签名和构建来源证明。
- 数据库迁移清单、前/后向兼容声明。
- 配置 Schema 版本和 Feature Flag 清单。
- API 合同、浏览器、队列、模型和恢复测试证据。
- 发布说明、已知限制、回滚方案和负责人。

手工从工作树直接发布不进入母控制台正式渠道。现有原子 Release 目录和 `verify.sh` 可作为制品/验收底座。

### 6.2 灰度顺序

```text
开发/测试 → 内部公司 → 5% 设计伙伴 → 25% → 100%
```

可按区域、Cell、公司、套餐和发布渠道分批。每批至少观察一个预设窗口，自动比较：

- HTTP 错误率、P50/P95/P99。
- Worker 失败、队列等待、死信和重试。
- 精确模型失败、Provider 429、熔断。
- 数据完整性、跨租户拒绝、审计写入。
- 成本/请求、Token/任务和异常突增。
- 用户关键流程成功率。

超过阈值自动暂停；满足明确条件才自动回滚。数据库破坏性迁移采用 Expand → Migrate → Contract，不依赖不可行的代码回滚。

### 6.3 公司版本策略

- `stable`：默认，经过完整灰度。
- `early_access`：设计伙伴，可提前体验，需接受条款。
- `pinned`：企业在支持窗口内锁版本；安全补丁可强制。
- `maintenance`：私有化/专属部署的维护版本。

版本锁有到期日，不能无限阻碍安全升级。

## 7. 可观测性

### 7.1 统一遥测

- Metrics：Prometheus/OpenTelemetry 指标。
- Logs：结构化日志，含请求/追踪/组织哈希/区域/版本，不含密钥和默认正文。
- Traces：API → 队列 → Worker → Provider 全链路。
- Events：业务、用量、发布、安全和审计事件。

进程内计数和数据库快照可保留为降级/核对，不作为唯一正式 SLO 真源。

### 7.2 监控维度

| 范畴 | 指标 |
|---|---|
| RED | 请求率、错误率、延迟 |
| USE | CPU/内存/磁盘/连接/队列利用、饱和、错误 |
| 业务 | 开通、登录、搜索、报告、AI、工作流成功率 |
| 租户 | 公司级错误、延迟、队列、配额，不泄露其他公司 |
| 模型 | 精确模型延迟、失败、429、Token、成本、质量抽检 |
| 数据 | 新鲜度、完整性、来源、同步、索引和回填 |
| 安全 | 登录失败、权限拒绝、导出、支持/紧急会话 |
| 商业 | 计量缺失、未归属成本、对账差异、毛利异常 |

### 7.3 SLO 初版

| 服务 | SLO |
|---|---|
| 登录与权限决策 | 99.95%，P95 <300ms |
| 控制台读接口 | 99.9%，P95 <500ms |
| 控制台同步写 | 99.9%，P95 <2s（不含异步执行） |
| AI/长任务受理 | 99.9%，2s 内返回 Operation |
| 审计接收 | L3/L4 99.99%，关键动作失败关闭 |
| 通知 | 高优先级 5 分钟内 99%，普通按摘要策略 |

AI 供应商实际生成时延单独统计，不混入“受理”SLO。

## 8. 审计

### 8.1 统一事件字段

```text
event_id / timestamp / region / environment
organization_id（平台纯全局事件可空）
actor_type/id / effective_actor / impersonator
session / support_session / emergency_session
action / resource_type/id / result
reason / ticket / approval
request_id / trace_id / IP / UA/device summary
policy/entitlement/release versions
before_hash / after_hash / metadata
```

### 8.2 强度分层

- 普通业务审计：事务 Outbox，最终投递；失败可有限重试。
- 高风险审计：先持久化审批和意图，执行后写完成回执；任一步无法保证记录则失败关闭。
- 不可变归档：每日分区哈希/签名，写入 WORM 对象存储并投递 SIEM。

热库建议 90 天；冷存储按合同/法规 1–7 年。租户可以查询自己的审计，不可修改；平台内部安全注释与客户可见字段分层。

## 9. 支持访问与 Break-glass

### 9.1 正常支持

- 先诊断平台运行元数据，不读取正文。
- 需要正文时列出具体资源、原因、时长和客户同意。
- 默认只读；写入需单独批准。
- 活动期间客户可见并可撤销。

### 9.2 紧急授权限制

- 仅事故处置，不用于常规运维便利。
- 15–60 分钟 TTL，精确公司/资源/动作白名单。
- WebAuthn/TOTP Step-up，跨租户写等需要第二人。
- 每次请求携带紧急会话 ID 并强审计。
- 自动到期，不可自延长，不可修改审计或授权他人。
- 创建、使用、撤销均实时通知安全团队；按合同通知客户。
- 结束后 24 小时内复盘。

现有永久 Owner/邮箱绕过和 body `force` 绕过均应退出生产路径。

## 10. 会话、密钥和供应链安全

### 10.1 会话

- 短期 Access Token + 可撤销 Refresh Token Family。
- 公司/成员暂停、密码重置、角色变化、风险事件触发撤销。
- 管理员和 L3/L4 操作强制 MFA；优先 WebAuthn。
- 设备列表、单设备退出、全部退出和异常通知。

### 10.2 Secret

- KMS/Vault 保存，数据库只存 Secret Ref 和版本。
- 最小工作负载访问、自动轮换、双版本过渡、使用审计。
- 日志、Trace、错误、导出和前端中统一脱敏。
- 密钥轮换先探测新版本、灰度、切换，再撤销旧版本。

### 10.3 软件供应链

- 锁定依赖、漏洞/许可证扫描、SBOM。
- 构建制品签名并验证来源。
- 分支保护、双人审查、Secret 扫描。
- 容器非 Root、最小镜像、只读文件系统和网络策略。
- 发布只接受 CI 产生且签名通过的不可变制品。

## 11. 隐私与数据治理

- 数据来源、采集时间、授权、保留和派生关系可追溯。
- 个人数据导出/删除（DSAR）与公司业务导出分开。
- AI 记忆默认候选确认，不静默变成长久事实。
- L2/L3 数据只发往满足区域/保留/合同要求的模型。
- 训练/质量采样默认不使用客户正文，需明确选择和脱敏。
- 数据删除覆盖主库、派生索引、对象、缓存；备份按自然过期并记录截止。
- 法律保留阻止删除时，向有权用户说明范围和依据。

## 12. 备份、恢复与灾备

| 资产 | 建议 RPO | 建议 RTO | 验证 |
|---|---:|---:|---|
| 身份/权限/权益 | ≤5 分钟 | ≤1 小时 | 月度恢复演练 |
| 核心业务数据库 | ≤15 分钟 | ≤4 小时 | 月度抽样、季度完整 |
| 审计 | 接近 0 | ≤4 小时查询恢复 | 每日签名与副本校验 |
| 对象/知识文件 | ≤24 小时或版本化 | ≤8 小时 | 季度恢复 |
| 搜索/向量索引 | 可重建 | ≤24 小时 | 定期重建演练 |

RPO/RTO 最终按套餐和区域调整。备份成功不等于可恢复；必须验证清单、解密、还原和业务一致性。

## 13. 事故响应

严重度：

- SEV0：跨租户泄露、平台控制权丢失、审计失效。
- SEV1：大面积不可用、严重数据损坏、错误计费/模型失控。
- SEV2：单区域/多租户降级、重要功能不可用。
- SEV3：局部缺陷或可绕行问题。

标准流程：发现 → 分级 → 止血/Kill Switch → 保护证据 → 通知 → 修复 → 验证 → 恢复 → 客户沟通 → 复盘与行动项。

SEV0/1 可触发 Break-glass，但不能借事故关闭审计。跨租户事件第一步是阻断相关路径/Cell，而非继续观察。

## 14. 运行验收门槛

- 每家公司有明确 Region、Deployment、Environment 和 Release 身份。
- 精确模型未就绪、预算未预留或策略未知时不发起付费调用。
- AI/抓取等付费路径 100% 进入统一 Reservation。
- ≥98% 供应商成本可归属公司，未归属 <2%，且有清理队列。
- Entitlement、Flag、Kill Switch、Permission 和 Quota 五类控制分离。
- 灰度可自动暂停；应用回滚 <10 分钟，迁移符合 Expand/Migrate/Contract。
- L3/L4 审计无法写入时动作失败关闭。
- 恢复演练达到承诺 RTO/RPO，并有可下载证据。
