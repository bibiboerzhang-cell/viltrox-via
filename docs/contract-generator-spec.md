# 合同生成器 · 一页 Spec(2026-06-12,候"施工"字)

> 裁令原文:"合同的展示主要是作为 2 个:一个是合同分析以及生成合同。可以手动输入合同的对方名字
> 我们名字还有我们公司名字对面的 id 以及付款账户什么的自动生成合同。以及可以做到对面提供和发票
> 输入进来合成一份完整合同。其次就是要直接中文+英文优化下这个。"

## 定位
合同归档 tab 升格为双功能:**分析**(既有 Claude 提取链,已上线)+ **生成**(本件)。
生成 = 模板化 + 双语(中文+英文逐条对照),不是自由 LLM 写合同——法务文本以模板为骨,
LLM 仅做可选润色(走队列,llm_ 标注,人工确认前不作真值)。

## 表单字段(生成输入)
| 组 | 字段 |
|---|---|
| 我方 | 公司名(默认 VILTROX/深圳唯卓仕,可改)· 签约人 · 联系邮箱 |
| 对方 | KOL 姓名/法名 · 平台+handle(从 assignment 自动带入)· 对方 ID/税号(选填)· 收款账户(银行/PayPal/Wise,选填) |
| 商务 | 金额+币种 · 里程碑付款拆分(默认 50/50)· 交付物清单(条目化:类型/平台/数量/截止日)· 授权范围(默认模板三选:仅有机/付费媒体 12 个月/永久买断)· 独占期(天)· 返工轮数(默认 2) |
| 发票合成 | 上传对方发票(PDF/图片)→ 走既有 Claude 提取链拿抬头/账户/金额 → 自动回填"对方"组并与表单冲突高亮 |

## 产出
- **双语合同文档**:中英逐条对照(条款编号对齐),HTML 预览 + PDF 下载(后端 weasyprint/reportlab,二选一按依赖现状)
- 文档落 R2/uploads + `vkpi_project_contracts` 新行(`source='generated'`),自动关联本 KOL assignment
- 生成即触发既有提取链回读(自校验:提取字段 == 表单输入,不一致标红)

## 模板
- v1 一套主模板(参照 Lindqvist 协议结构:Deliverables/Usage rights/付款/违约/解约/返工)
- 模板文本存 `backend/app/domains/projects/contract_templates/`(版本号目录),条款 key 化,中英成对
- 法务红线:模板正文改动需留痕(git);LLM 润色输出必须 diff 展示、人工确认才入档

## 队列与闸
- 发票提取复用 `project_contract_extract` 链(已队列可见)
- LLM 润色(可选)新 job_type `contract_polish`,闸 A:单次 < $0.2,默认关
- 无新增评分语义,零触 fit_score

## UI(合同归档 tab)
- 顶部双 pill:「分析(上传已有合同)」「生成(新合同)」
- 生成页 = 表单(上述字段)+ 右侧实时双语预览 + [生成 PDF][发票回填] 按钮
- 中英优化同步覆盖既有分析视图:字段标签全部"中文 (English)"双标

## 工程量
后端:模板引擎+PDF 渲染+生成端点+发票回填端点(~1.5 件);前端:生成表单+预览(~1 件);
依赖:PDF 库选型(闸 B:新依赖入 requirements 需报备)。

## 验收
表单最小集(我方/对方/金额/1 条交付物)→ 生成双语 PDF → 归档行出现且提取回读一致;
发票上传 → 对方组字段自动回填。
