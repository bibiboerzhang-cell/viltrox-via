# V-KPI 全平台架构报告

日期: 2026-07-07 | 基线: `063d0b7e` / codex/dashboard-real
方法: 5 路并行深读(后端/前端/前后端集成/LLM 降级链/数据调度安全)+ 本地栈实测。规模:后端 1124 个 .py、前端 645 个 .tsx/.ts、375 个 SQL 迁移、157 个 router、29 个 nav 板块。

---

## 0. 一句话架构

**React SPA(Vite)+ FastAPI 单体的同源集成**:线上单服务(8102/8001)同时供 API 和前端静态资源。后端用一套 SQLite 语法书写、运行时经 compat 双栈层翻译打到生产 Postgres;所有 LLM 走唯一网关 `llm_gateway.invoke()` 的三家云降级链 + 规则兜底;权限三层纵深防御。

## 3. 前后端集成关系(一次请求怎么穿透)

### 认证 = 双钥设计
一次 `/api/auth/login` 同时下发:
- **Bearer token**(存 localStorage,供普通 XHR/apiFetch);
- **httponly cookie `via_token`**(供 EventSource/SSE——因为 SSE 无法设 Authorization 头)。

后端 `get_current_user` **优先 Bearer、回退 cookie**,verify 后挂 staff 上下文(permissions/is_owner/staff_id)并 TTL 缓存。

### 授权 = 三层纵深防御
```
① 中间件 admin_rbac: 按 path 前缀映射粗粒度 tab/level (/api/admin/kol→kol_ops)
② 端点 Depends(require_tab/require_permission/manager_guard): 细粒度闸(分档:佣金≤15%员工/>15%管理层)
③ domain access.scope: effective_staff_id 产 SQL 过滤片段(每用户只见自己数据,owner/can_view_all 放开)
```
**关键**:前端拼的 `&staff_id=` 只是 hint,真正的隔离在 domain 层 scope,前端骗不了。

### 一次完整穿透(GTM Command 读路径)
```
前端 getGtmPlanPreview → apiFetch(GET /market-brain/gtm-plan/preview?sku..&budget..&goal.., Bearer, 60s)
  → [CSRF→admin_rbac→db_scope] → 路由 Depends(require_tab('vkpi','read'))
  → domain market_brain.gtm_plan_preview → get_conn() → compat 翻译 SQL → PG
  → 返回 {meta, public_plan{thesis/forecast/market_opportunity/kol_candidates/.../budget_mix}}
  → gtmCommand-api 规范化+过滤私有字段 → 前端 useCachedGet 渲染(切 tab 不重拉)
```

### 实时/异步三链
- **SSE 优先+轮询兜底**:`useEventStreamOrPoll` → EventSource(withCredentials,靠 cookie)→ 后端 progress/center/stream + activity/stream(4-5s diff 变化才推帧);不可用无感回退轮询。
- **导出任务**:create_export → export_jobs 落文件 → download_url。
- **本地 Worker**:runner/浏览器 → register 拿 device_id → lease{task_types} → registry 签 HMAC 短期 token → 本机跑四类安全活 → submit → 服务端深校验落 staging。

## 4. 🔑 LLM 失败重调与备选方案(重点)

**核心机制:跨-provider 降级链,不是 provider 内重试。** `llm_gateway.invoke()` 是全平台唯一同步 LLM 入口,约 20 个子系统以 `purpose + preferred_provider + max_output_tokens` 三参调它。

### 一次 invoke 的完整决策树
```
invoke(prompt, purpose, max_output_tokens, preferred_provider, ...)
  ↓ clamp max_output_tokens = max(16, n)   ← 本session修复,防OpenAI 400
  ├─ prompt 空 → rule_v0 兜底 (provider='rule_v0') [终:没用AI]
  ├─ 遥测预算①②: 超预算只记 budget_warnings,【不阻断】(record_only)
  └─ for provider in _ordered_providers(preferred):   基序=(openai, google, anthropic, rule_v0)
      │   preferred 参数 / env LLM_PRIMARY_PROVIDER 可把某家提到最前
      ├─ rule_v0 → continue(循环内不主动调)
      ├─ 未配置(key空) → errors.append('not_configured') → 下一家
      ├─ 未实现 → errors.append('not_implemented') → 下一家
      ├─ enforce 预算超支 → 记零成本台账 + errors.append('budget_blocked') → 下一家【不发网络请求】
      ├─ result = caller(prompt, max_tokens)   ← _call_openai/google/anthropic:一次 urllib POST，无重试
      │   ├─ status=success 且 text 非空 → 返回 (fallback_used=bool(errors)) [终:用了AI]
      │   └─ 否则(4xx/5xx/网络异常/text空) → errors.append → 继续下一家
      └─ 三家全败 → rule_v0 确定性兜底(不计费、不 raise)[终:没用AI]
```

### 备选方案层次
1. **三家云降级**:google(若设为 primary)→ openai → anthropic,任一成功即返回;
2. **规则兜底 rule_v0**:三家全败的最终安全网,规则生成、永不失败、不计费、不抛异常;
3. **预算感知跳过**:enforce 层超预算的 provider 直接跳过不发请求;
4. **key 池轮转**:配了 Fernet 才查 `vkpi_api_key_pool` 轮转取运行时解密明文,池空回退 env key;
5. **省钱两路**:Gemini 上下文 cache(ttl 3600s)+ 结果 cache + LLM Batch(Anthropic 50% 折扣,默认关)。

### ⚠️ 六个关键陷阱(排障必读)
1. **`fallback_used=True` ≠ 用了 rule_v0**:它 = `bool(errors)` = 过程中是否发生过 provider 降级。即使 anthropic 最终成功、但前面失败过,它仍是 True。**判"真没用 AI"只能看 `provider=='rule_v0'`**。
2. **provider 内零重试是有意设计**:瞬时 429/5xx 不本地重试同一家,直接换下一家。要抗抖动得靠上层(如 content_fit 的 `_attempt` 循环)自己再调 invoke。
3. **gemini-flash 小 token 返空 text 被判失败降级**:思考型模型思考 token 与输出共享预算,token 给太小(实测 1200)思考吃光、text 空(HTTP 仍 200)→ 被判失败降级。真凶已修多处(→4096)。
4. **代理必须经 runtime_env.sh**:本网络下三家全被墙,`HTTPS_PROXY=YTDLP_PROXY`;漏 source 这段 → 全链降级 rule_v0(看似"AI 失灵"实为代理没导出)。
5. **budget_preflight 默认 require_configured=True 易误判**:运营诊断视图会把无 caps 行的 scope 当硬拦报 hard_stop,而主线 enforce 走 require_configured=False，口径不同。
6. **月度预算默认 $0**(有意):.env 不随 rsync,`LLM_MONTHLY_BUDGET_USD` 缺失→显示 $0 遥测噪音,部署后需手补。真正卡死是 enforce 层 provider/single_call caps。

### ModelRouter 是预埋脚手架
`models/router.py` 的 route_and_invoke 生产**零调用方**——所有真实调用都直接调 `invoke` 并手写 preferred_provider。别误以为多 key 池轮转选型已在跑。

## 5. 支撑层(数据/调度/worker/安全/可观测)

- **数据层**:整个后端写 SQLite 语法,compat shim 运行时翻译到 PG(?→%s、date('now')→PG、GROUP_CONCAT→STRING_AGG);glob 自发现迁移(序列尾 226,新增免改 manifest);`db_migration_max` 读真实已应用集(schema_migrations)非代码声明。
- **调度**:APScheduler,`scheduler_tasks` config-gate 默认 OFF;本 session 新增 job(两 GTM+对账+周 rollup+日基线+drift 哨兵),时区 CHINA_TZ。
- **worker/队列**:apify_jobs_worker SKIP LOCKED 三档优先+四车道;local_workers 设备/租约/HMAC 短期 token + 浏览器协助。
- **安全**:permissions.py 权限矩阵；manager_guard 分档闸(佣金 0-15% 员工/>15% 管理层)；读裁决（AI 花费仅管理层、GMV 员工可看）；scope 按 effective_staff_id 隔离。
- **可观测**:/health trust 块(sha 对齐+db_migration_max+worker 心跳);request metrics 快照；SENTRY_DSN。

### 五个数据层陷阱
- BOOLEAN 读回是 int 1/0(`is True` 全 falsy,用 _truthy);
- 迁移注释禁 ASCII `?` 和 `%`(compat 占位符翻译会炸);
- worker 双认领毒化(主 worker 须 local_lease_id IS NULL + job_type 两道过滤);
- 连接池自愈(deep_crawl 关全局池致后续 job 全灭,_get_pg_pool 发现 closed 即重建);
- cost 精度用 `cost_micro_usd` 列（旧 cost_cents 整除曾归零致预算闸失效）。

## 6. 架构评价(严苛)

**强**:分层清晰(router 薄壳/domain 真源/access 单源)、compat 让一套代码跑本地+生产、LLM 降级链有规则兜底永不崩、权限三层纵深。

**弱**:①无 ORM，343 文件手写 SQL，compat 层是隐性复杂度(占位符/BOOLEAN/时区陷阱反复咬人);②前端 chunk 预算已到临界(0.3KB),createElement 债 107 文件;③三套报表实现并存;④ModelRouter/bandit/key 池轮转多是预埋脚手架非生产在跑;⑤LLM provider 内零重试,瞬时故障直接降级弱模型/rule_v0，抗抖动靠各 caller 自觉。
