## 一、入口结构(三分支总闸实测)

```
用户输入 → SmartKolInputPanel
            ├─ 前端 detectMode(:54-64)  ← 只控按钮图标/文案,【不参与真实分流】
            └─ run() 恒发 mode:"auto" → POST /kol-smart-search
                                          └─ 后端 _looks_like_url(:79-85)【真闸门】
                                              ├─ url   → kol_url_deep_crawl.classify_url
                                              │           ├─ video   → 建档/只析 → job_type=video →〔video深析/思考〕
                                              │           ├─ profile → 账号增量/全量
                                              │           └─ unknown → 残废 url 会话
                                              └─ recall → recall_kol_profiles(向量语义召回)
                                                          └─ 点"后台深度查找"→ smart_search_profile_advance →〔智能查找/搜索〕
```

**真闸门是后端 `_looks_like_url`(vkpi_kol_pool.py:79-85),前端 detectMode 形同装饰。** 这是后续多个误判的总根。

## 三、探针 5 命门 · 泳道整圈实测留痕(lane-1 亲跑)

入队 1 条废数据真任务,polling `/task-queue/compact`(2.5s 间隔)亲眼观测一整圈:

| 时刻 | queued | running | active[0] | 桶/阶段 |
|---|:--:|:--:|---|---|
| t0 | 1 | 0 | 944 智能查找 | **queued** |
| t≈3s | 0 | 1 | 944 智能查找 | **搜索/search** 🟢 |
| t≈18s | 3 | 1 | 945 video深析 | **思考/thinking** 🟢 |
| 终态 | — | — | 944 done(15s)/945 done | recent 回填 🟢 |

**命门逐项判定:**
- ✅ **三桶真现**:搜索(search)🟢、思考(thinking)🟢 现场逮到;总结(summarizing)桶代码映射确认(queue_view.py:174 `account_dossier_extract/report/summary→summarizing`),实跑中 949/950 账号沉淀任务在途排队、42s 窗未逮到 running 瞬间。
- ✅ **终态回填**:944/945 done 后进 recent[],`recent_by_status:{done,failed}` 真实区分。
- ✅ **失败显原因**:job 946(video)失败 → recent[] 带 `error:"RuntimeError: media_resolve_failed"`、`error_category:"media_resolve"`、stage_label「思考」。**点了有下文,失败有因。**
- ✅ **前方 N 个**:`ahead_count` 正确(948=1、949=2、950=2)。
- 🔴 **ETA「约 X 分」爆表【P1 命门 BUG】**:`eta_seconds` 渲染出天文数字——948 排 1 个前车 = **338305s≈3.9 天**;949 = **336394s**;950 = **345034s**。前端「约 X 分」会显示 ~5600+ 分钟。
  - **根因坐实**:`_avg_duration_by_job_type`(queue_view.py:274-285)用 `AVG(updated_at - created_at)` 当"处理时长"——这是**墙钟(建档→完成,含排队等待)**而非真处理时间。DB 实测 `video` 任务 n=176,avg_wall=**676611s≈7.8 天**,中位数 **738969s≈8.55 天**(中位数也爆表 → 系统性队列积压,数天前堆的 video backlog 正排空,非个别离群)。
  - apify_jobs **无 `started_at` 列** → 无法测纯处理时长;中位数法也救不了(中位数同样爆表)。

## 五、修复序(按价值 × 闸)

> 总纲:**先堵烧钱与口径假象(P0-1/P0-2),再修命门体验(P1-1 ETA),再清状态卡虚标。** 注:KOL Pool 评分红线区(`viltrox_fit_score` / `enrich_item` / `run_kol_pool_gemini_single` / rule_v0)不在本批触碰范围,以下修复均绕开评分写点。

### 第一序(P0,需先过闸 / 拍板)
1. **P0-1 真增量落地**〔闸B〕:把 `incremental_state.last_video_at`(改用专列 `last_video_seen_at`,见 P1-4)作为 `since/oldest_post_date` 透传进爬虫 actor input,在**抓取层**截断而非抓后过滤。→ 直接省 458 账号的重抓配额。**改 Apify actor 输入契约 = 闸B,需报备。**
2. **P0-2 三环闭环**〔闸C〕:`list_available_project_kols` SELECT 加 `EXISTS(vkpi_kol_pool_favorites f WHERE f.kol_pool_id=p.id AND f.staff_id=本人)` 过滤(或前端按收藏子集拉)。→ 这是乙案"收藏即跟进归宿"的真地基,**需 Jianbo 拍板:选择器候选是「全池」还是「我的收藏子集」**(语义口径)。
3. **P0-3/P0-4 a+ 断头**〔无闸〕:新人视频流 crawl 阶段直接 `mode=account_deep` + 全量 `max_posts`(或 history 段用全量重新 `crawl_channel_videos`),消除"名义全量、实际 3 条"。

### 第二序(P1 命门 + 口径)
4. **P1-1 ETA 修复**〔闸B〕:apify_jobs 加 `started_at` 列(worker claim 时写),用 `AVG(updated_at - started_at)` 算真处理时长;或**立即止血**:`_dur()` 加上限 clamp(如 ≤600s)+ 过滤 `created→done > 1h` 的离群样本。
5. **P1-2/P1-3 分流闸收口**〔闸C〕:`_looks_like_url` 加 host 强校验——netloc 必须无空白/非 ASCII 段且命中已知平台域(youtube/instagram/tiktok)或通过 DNS-label 白名单;CJK/punycode 主机一律回退 recall。
6. **P1-6 中文召回**〔闸C〕:确定性 natural_search 对 CJK 做 n-gram/2-gram 或接 jieba / PG 全文(pg_trgm),终结整句 LIKE 哑火。
7. **P1-4 游标消歧**〔无闸〕:增量改读写专列 `last_video_seen_at`(爬完才推进),或删该死列;切勿用被 profile 回填的 `last_video_at` 当游标。

### 第三序(状态卡诚实化 + P2)
8. **P1-8/P1-9/P1-10 + P2-5 状态卡**〔闸C 语义〕:本周Trend 接真时序或改标「待接入」;月度Reach 改名「avg_views 总和」或接真 reach 模型;新发现/待补全要后端真 `candidate_kind`;平均V6Fit 卡名明示"旧静态分,未含 RealER 影子"。
   - **⚠ 口径校准(裁决⓪追加,做 P1-8/9/10 时必校)**:凡以 `COUNT(viltrox_fit_reason)` 当分母的统计(评分覆盖率/已评估比例/平均分分母等),**必须排除空串行**(`WHERE viltrox_fit_reason <> ''` 或 `NULLIF(viltrox_fit_reason,'')`)。实测 `COUNT(reason)=1128` 含 0号 RealER 重抓的 5 个 `reason=''` 空串占位行(id 5663-5667,fit_score=NULL),**真带分仅 999**。直接用 1128 当分母会虚增评分覆盖率(应为 999/1128 而非 1128/1128)。
9. **P1-5/P1-7 可见性**〔无闸〕:run summary / available 返回体暴露 `爬虫实拉条数` / `total` / `has_more`,消除"没烧钱"与"看到全部"假象。
10. **P2-1/P2-2 口径一致**〔无闸〕:detectMode 文案改"自动识别"或前端为准;新人账号同步走 enqueue 入队让泳道可见(与"所有 LLM 进队列"裁令对齐)。
