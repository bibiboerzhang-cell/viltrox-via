## 四、确定性机制(回答"对每一步的确定性")

1. **每步四道闸**:tsc / pytest / 红线 grep / 部署后线上验证(路由表+功能冒烟)——今天三波已跑通此流程 30+ 提交零回滚。
2. **收敛后部署确定性**:P0 之后不再有锚点补丁/旧布局炸站类风险(今日闭环演习抓到的"缝合怪断环"即此类,收敛根治)。
3. **功能自证**:P4 起每个智能功能的输出都进预测台账——功能好不好不靠感觉,靠命中率数字。
4. **回归护栏**:哨兵 10 项日检 + 成本记账 + 活动流,任何一步引入的退化 24h 内可见。
5. **本图即状态板**:每阶段完成后我更新此文档的验收栏(✅/日期),你随时打开就知道走到哪。

## 七、L 轨道:本地大模型学习(2026-07-03 新增,与 P2-P6 并行)

> 终极护城河动作:用自有闭环数据训练自有模型。架构已预埋:
> `training_export.export_training_dataset` 可导训练集;ModelRouter 注册表已有

| 阶段 | 内容 | 前置 | 确定性 |
|---|---|---|---|
| **L1 数据整备**(P2 后启动) | 训练集导出扩四类样本:KOL特征→转化标签 / 帧级特征→内容表现 / 外联话术→回复 / Intelligent问答对;质量清洗+版本化落 R2 | P2 出标签(outcomes/GMV) | 🟢 |

| **L3 领域 LoRA**(第 4-6 周) | 开源模型(Qwen 类)LoRA 微调:369 SKU 知识库+历史问答+brief 范例 → 镜头领域营销助手;跑在你 Mac(MLX/ollama)或既有 GCE;ModelRouter 路由:高频/低敏/低成本任务走本地,复杂推理走云 | L1;GCE/Mac 算力 | 🟡 样本量初期靠知识库+合成数据 |
| **L4 持续学习**(常驻) | 预测台账对账结果自动回流训练集;月度重训;模型版本进 registry,新旧模型影子对比(shadow eval)胜出才切换 | L2/L3 + 台账 | 🟡 |

**L 轨道的两个纪律**:①永不让模型直接写生产事实(只出建议/评分,过预测台账验证);②本地模型上线必须先影子跑赢现有基线(评估框架 evals.py 已有)。

|---|---|---|
| **SP-API(卖家API)** | 按 SKU×站点的真实订单/销量、ASIN 流量与转化率、库存水位 | P2:焦段矩阵需求维度从估算→真实销量;库存调度输入 |
| **Amazon Attribution** ⭐ | 每个 KOL 一条带归因标签的 Amazon 链接:点击→浏览→加购→**购买**全归因(14天窗口,Ads API 回流) | P2:双轨归因(Shopify+Amazon),转化可见度 20-40%→**70-80%**;外联包双链发放(goaffpro短链+Attribution链) |
| **Brand Analytics** | Amazon 站内搜索词表现(掏钱包前最后一步)、购物篮、复购 | P3:A 级信号新增一路,比 Google Trends 硬一个量级 |

**你侧动作(并入 P0,与 webhook 同级、建议更优先)**:①Seller Central 管理员 + SP-API 开发者注册(审批数天);②Brand Registry 状态确认;③Amazon Ads 开 Attribution 权限。

## 廿三、产品化双轨:内部版 vs SaaS 版

**内部版(现在-未来 6 个月的唯一形态)**:服务 Viltrox,要深度/定制/闭环,不要 billing/注册/泛化。
**SaaS 版(Category Marketing Brain)**:tenant/品牌配置/产品本体/注册/配额/试用工作区/样例数据/billing/onboarding/权限模板/删除导出/白标。
**泛化开闸条件(=十四节里程碑闸门,同一套标准不另立)**:内部跑出 1-2 个真实战役案例 + 预测命中率>65% + 双轨归因稳定 → 才动 SaaS 第一行代码。
