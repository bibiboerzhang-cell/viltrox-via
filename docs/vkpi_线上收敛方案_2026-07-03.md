# 线上收敛方案(prod 升级到 HEAD)· 2026-07-03

> 目的:把线上从「冻结 8d052c95 + 约 30 个锚点补丁/热修文件」一次性升级到本地 HEAD,
> 消掉全部旧布局债。之后部署回归普通 rsync,不再需要逐文件 parity + 锚点移植。

## 为什么现在值得做

- 仅 7/3 一天:10+ 个锚点补丁、6 个部署坑(缺模块炸站/权限炸站/迁移锁死/丢 prefix/pkill 自杀/rsync 权限),全部根因 = 新旧布局分叉。
- 分叉每天变大(本地领先约 90 提交),锚点补丁是给债付利息。
- **迁移无缺口**:本地与线上 db_migration_max 均为 209,收敛不涉及任何 DB 结构追赶。

## 前置核对(执行前一天完成,全部只读)

1. **文件全量 diff 清单**:`rsync -n` 干跑列出将变更/删除的文件,人工过一遍删除项(防误删线上独有的热修产物——理论上没有,全部热修已回流本地提交)。
2. **env 缺项清单**(部署不带 .env,历史教训 LLM_MONTHLY_BUDGET_USD):对照本地 `config.py` 全部 `os.environ.get` 键,列出线上 .env 缺失且默认值会关功能的键,交用户补(用户自己加,不代改)。
3. **服务清单**:web(:8001)/ worker(单进程串行)/ vkpi-sync-daily.timer / vkpi-health-sentinel.timer;确认 ENABLE_SCHEDULER=1 且 `--workers 1`(防调度器双跑,6-18 教训)。
4. 本地全绿:pytest 全套 + py_compile 全仓 + tsc + build。

## 执行窗口

低峰:建议中国时间凌晨 03:00-04:00 之前完成(避开 04:00 sync)= 美西白天,预计中断 < 5 分钟。

## 执行步骤(约 20 分钟)

1. **备份**:`tar czf /opt/backup/viltrox-pre-converge-$(date +%m%d).tgz /opt/viltrox-2.0/{backend,scripts,migrations,frontend/dist}` + `pg_dump`(结构+关键表)。
2. **停 worker**(pkill 正则转义防自杀:`pkill -f "app[.]workers[.]apify_jobs_worker"`)。
3. **整仓 rsync**:backend / scripts / migrations / frontend/dist(排除 .env、runtime/、uploads/;`--chmod=F644` 防权限坑)。
4. **BUILD 戳**:写 BUILD_GIT_SHA/BRANCH/TIME(deploy 脚本同款),/health 的 git_sha 终于对齐 HEAD,「⚠不一致」消失。
5. **import 全链验证**:`.venv/bin/python -c "import app.main"`(7/3 教训:parity 不保依赖)。
6. **重启 web** → /health 轮询(迁移自动 apply,应无新迁移)→ **起 worker**。
7. `pip install -U yt-dlp`(deploy 脚本惯例)。
