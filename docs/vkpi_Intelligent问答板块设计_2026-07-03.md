# Intelligent 问答板块设计 · 2026-07-03

> 目标:前端一个框,问任何营销问题 → 系统结合当前数据给**结论+证据+可执行方案**,
> 且答案不是死路,点一下就变成动作,动作结果回流让下次更准。简单、快、闭环。

## 一、不做什么(避免变成"又一个 ChatGPT 框")

- 不把每个问题丢给 LLM 自由发挥(慢、贵、会编)。
- 不做纯文本回答(用户要的是"能点的方案",不是一段话)。
- 不做无证据的结论(每个答案必须挂它读了哪些真实数据行)。

## 二、核心架构:三车道路由(cheapest-capable-first)

一个问题进来 → 意图分类(已有 query_planner.match_intent)→ 走最便宜够用的车道:

| 车道 | 问题类型 | 引擎 | 延迟 | 成本 |
|---|---|---|---|---|
| **① 事实道** | "哪个国家增长最快""谁收样没发内容""本月ROI最高的KOL" | query_planner 预置安全SQL(已有 `/analytics/ask`) | <500ms | 零LLM |
| **② 检索道** | "找像 eliinfante 这样的人""适合85mm的KOL" | semantic_recall + unified_search(已有) | <2s | 零/极低 |
| **③ 推演道** | "为什么该推这个""下月预算怎么分""给我一个Z卡口战役" | 检索上下文 → LLM合成 + 技能编排(campaign_plan等已有) | 流式 | 预算闸内 |

**关键**:80% 的日常问题落①②道,秒回、不烧钱;只有开放式"为什么/该不该/给方案"才进③道。
路由器 = 现成意图分类器 + 兜底 LLM 分诊(仅模糊问题)。

## 三、答案卡的统一形态(每个回答都长这样)

```
┌─ 结论(一句话,加粗)──────────────────────┐
│ "本月该加注 Z 卡口:需求↑23%,你有 3 支货,竞品弱覆盖" │
├─ 证据(可点,钻取到源)────────────────────┤
│ [Trends Z卡口 +23%] [库存3 SKU] [竞品雷达: Viltrox 声量31%] │
│ 置信度 高 · 数据新鲜 今日 · 读了 47 行                    │
├─ 可执行方案(1-3 个按钮)──────────────────┤
│ [圈出 Z 生态 KOL TOP10 →入池]  [生成战役brief]  [立预测] │
└──────────────────────────────────────┘
```

- **结论**先行、可扫读;**证据**默认折叠可展开、每条可点进详情;**动作**最显眼。
- 没数据时诚实说"样本不足",不编。

## 四、闭环:答案 → 动作 → 执行 → 学习(这是和 ChatGPT 的根本区别)

```
问 ──▶ 答(结论+证据) ──▶ 点[执行] ──▶ 落 Action Inbox / 起 workflow
                                              │
       预测台账 ◀── 到期对答案 ◀── 业务事件回流 ◀┘
        │
        └─▶ 命中率↑同类建议权重;打脸→反例入记忆,下次这个问题答得更准
```

- 每个带主张的动作("推这5个预计90天N单")点执行时**自动立一条预测**入台账。
- 系统为自己的回答负责,而且**越用越准**——这是可证伪的"智能",也是 Intelligent 板块的护城河。

## 五、简单 & 快的 UX

1. **一个框,永远在**:独立 Intelligent tab + 全局 ⌘K 唤起(任何页面都能问)。
2. **永不空白**:框下方是**今日建议问题 chips**,由当天数据异动种出来——
   - 品牌脉搏有负面异动 → "今天为什么负面涨了?"
   - 焦段矩阵出主推格 → "现在最该推哪个焦段?"
   - 有KOL收样超7天没发 → "哪些合作该催了?"
   - 用户永远面对"点一下就有洞察",不是"面对空框不知问啥"。
3. **快**:①②道秒回并缓存;③道流式吐字(先给结论骨架再补证据);相同问题当天命中缓存。
4. **可追问**:答案下方"继续问"——基于上一个答案的上下文深挖(会话式,但每轮仍挂证据)。
5. **可钉**:好答案钉到 Dashboard 变成常驻卡(如"每周焦段矩阵")。

## 六、落地批次(全部基于已有零件,不从零造)

- **v0(2-3天)**:Intelligent tab + 框 + 接现成 `/analytics/ask`(事实道全通)+ 答案卡形态 + 建议问题chips(种3-5个)。**当天就能"问数据得答案"**。
- **v1(3-4天)**:接检索道(找人/找相似)+ 接③推演道(LLM合成,RAG over 证据)+ 动作按钮落 Action Inbox。
- **v2(1周)**:动作→预测台账→学习回流;⌘K 全局唤起;追问会话;钉卡。
- **v3**:接品牌脉搏/焦段矩阵/机身日历作为证据源,答案质量随信号接入升级。

## 七、和现有板块的关系(不重复造)

- 复用 query_planner(事实)、unified_search(检索)、skill_orchestrator+5技能(方案)、llm_gateway(合成)、Action Inbox(动作落地)、预测台账(学习)。
- Intelligent 板块 = 这些能力的**统一自然语言入口**,不是新引擎。
- 它是整个 v2 方案的"驾驶座"——把散在各页的智能,收成一个"问一句就给方案"的框。

## 一句话
**别的系统:你查数据,自己想结论。V-KPI Intelligent:你问一句,它给结论+证据+能点的方案,还替自己的判断立字据、越用越准。**
